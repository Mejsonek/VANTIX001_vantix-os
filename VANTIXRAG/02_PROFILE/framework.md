# framework.md — Framework Decyzyjny Kacpra

> Jak Kacper podejmuje decyzje. Używane przez agenta do rekomendacji spójnych z jego logiką myślenia.

---

## Główny filtr decyzyjny

Przed każdą decyzją biznesową — jedno pytanie:

> **Czy to zbliża mnie do 80k PLN/rok i do 75k PLN poduszki finansowej?**

Jeśli tak → rozważ. Jeśli nie → odłóż lub odrzuć.

Drugi filtr (długoterminowy):

> **Czy za rok będę żałował, że tego nie zrobiłem?**

## Framework priorytetyzacji zadań

### Hierarchia priorytetów Kacpra

```
1. Cashflow (przetrwanie i spłata długu)
2. Budowanie systemu (Vantix OS — leverage)
3. Nauka (angielski, sprzedaż, biznes)
4. Wszystko inne
```

### Kiedy coś dostaje priorytet
- Blokuje cashflow → **natychmiast**
- Blokuje inną pracę → **dziś**
- Zbliża do celów rocznych → **ten sprint**
- Fajny pomysł bez bezpośredniego efektu → **backlog / odrzuć**

---

## Zasady podejmowania decyzji projektowych

### 1. Działające > ładne
MVP ma działać, nie wyglądać. Dopracowanie przychodzi w fazie 3. Kacper nie blokuje postępu przez perfectionism.

### 2. Prostota > sprytność
Prostszy kod, prosta logika, prosta architektura — nawet jeśli "sprytniejsze" rozwiązanie wydaje się eleganckie. Złożoność zabija tempo.

### 3. Dowieź → oceń → skaluj
Nie planuj skalowania zanim nie ma czego skalować. Automatyzuj sprzedaż po tym jak masz działający proces, nie przed.

### 4. Najpierw ręcznie, potem automatyzuj
Jeśli proces nie istnieje → nie automatyzuj. Najpierw zrób ręcznie, zrozum gdzie są problemy, potem buduj automatyzację.

### 5. Jeden front na raz
Nie rozpraszaj się na wiele inicjatyw jednocześnie. Priorytet: **dowiezienie kapitału i stabilizacja finansowa** zanim wejście w kolejny projekt.

## Framework oceny nowego projektu / klienta

Przed przyjęciem projektu sprawdź:

| Pytanie | Próg |
|---------|------|
| Czy budżet ≥ 1 000 PLN? | Tak → kontynuuj |
| Czy klient ma konkretny problem (nie "najtańsza opcja")? | Tak → kontynuuj |
| Czy branża pasuje do ICP (agencja / usługi / e-commerce)? | Tak → kontynuuj |
| Czy decydent rozumie wartość automatyzacji? | Tak → kontynuuj |
| Czy projekt zbliża do 80k PLN/rok? | Tak → priorytet |

Czerwone flagi → odrzuć lub filtruj na etapie kwalifikacji CRM:
- "Najtańsza oferta"
- Brak określonego budżetu
- Brak konkretnych oczekiwań
- Negocjowanie Blueprintu (filtruje niepoważnych klientów)

## Framework oceny nowej technologii / narzędzia

Przed dodaniem nowego narzędzia do stacku:

1. **Problem** — jaki konkretny problem rozwiązuje?
2. **Koszt** — ile PLN/mies. dodaje do kosztów stałych?
3. **Alternatywa** — czy nie można użyć czegoś co już mamy?
4. **Lock-in** — jak trudno będzie z tego wyjść?
5. **Kiedy** — czy przychód uzasadnia ten koszt teraz?

Zasada: **utrzymuj koszty stałe poniżej 300 PLN/mies.** do osiągnięcia stabilnych przychodów 15k PLN/mies.

## Framework reagowania na presję

Gdy jest trudno (brak klientów, napięty cashflow, niepowodzenie):

1. **Reset** — krótki moment "odstresowania" zanim wróci do pełnej efektywności
2. **Diagnoza** — co konkretnie nie działa? Gdzie jest bloker?
3. **Najmniejszy następny krok** — co mogę zrobić teraz, w tej chwili?
4. **Nie podejmuj dużych decyzji z pozycji strachu** — poczekaj na reset

Wewnętrzny anchor: *"Czy za rok będę żałował, że tego nie zrobiłem?"*

## Framework nauki

Kacper uczy się przez budowanie, nie przez kursy.

**Zasada:** problem → budowanie → efekt → nowa wiedza

Przed każdym nowym projektem lub modułem:
- Co nowego się przy tym nauczę?
- Czy ta wiedza zbliża do celów rocznych?
- Czy mam wystarczający kontekst żeby zacząć?

**Priorytety nauki 2026:**
1. Angielski — odblokuje rynek globalny
2. Zarządzanie biznesowe — wycena, skalowanie, procesy
3. AI w architekturze — przez każdy projekt Vantix

## Instrukcja dla agenta

Gdy Kacper pyta "co robić dalej" lub "czy warto" — odpowiedz przez pryzmat tych filtrów:
1. Czy to zbliża do 80k PLN/rok?
2. Czy to nie jest scope creep poza bieżącą fazą?
3. Czy najpierw nie powinniśmy odblokować obecnych blokerów?

Nie dawaj odpowiedzi bez kontekstu finansowego — Kacper podejmuje decyzje w środowisku ograniczonych zasobów.
